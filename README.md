# 가족 여행 일정표

백엔드 없이 GitHub Pages에서 바로 동작하는 **모바일 친화적 가족 여행 일정표**입니다. 여행이 바뀔 때마다 `trips/` 안의 JSON만 교체/추가하면 됩니다. (빌드 과정 없음 · Vanilla JS)

## 구조

```
index.html / style.css / app.js   # 웹앱 (수정 불필요)
trips/index.json                  # 여행 목록 (드롭다운에 표시)
trips/<trip-id>.json              # 여행별 상세 일정
```

## 주요 기능
- 원본 계획(읽기 전용) ↔ 변경된 일정(localStorage 자동 저장) 전환, 변경 항목에 `변경됨`/`추가됨` 뱃지 및 기존 시간·이름 취소선 병기
- 시간/소요시간 수정, 일정 추가·삭제 시 같은 날 이후 일정 시간 자동 연쇄 이동 (상단 체크박스로 on/off)
- 일자별 경로 바 + 구글 지도 전체 경로 버튼, 장소명 → 구글 지도 검색 링크 자동 생성
- 식사 1·2·3안 선택기, 우천 시 대체 코스 스위치, 다크/라이트 테마

## 새 여행 JSON 추가 방법
1. `trips/2026-08-fukuoka.json`을 복사해 `trips/<새-id>.json`으로 만듭니다. (예: `2027-02-sapporo.json`)
2. 내용(제목, 항공, 숙소, 일정)을 바꿉니다. 장소는 `q`(구글 지도 검색어)만 넣으면 지도 링크가 자동 생성됩니다.
3. `trips/index.json`에 항목을 추가합니다.
   ```json
   { "id": "2027-02-sapporo", "title": "삿포로 여행", "dates": "2027.02.10 ~ 02.14", "start": "2027-02-10", "end": "2027-02-14" }
   ```
   (`id`와 파일명이 같아야 합니다. 다르면 `"file": "파일명.json"` 지정)
4. 커밋 & 푸시하면 Pages에 반영됩니다. 상단 드롭다운에서 과거·예정 여행을 전환해 볼 수 있습니다.

### 일정 항목 필드
| 필드 | 설명 |
|---|---|
| `id` | 일정 고유 ID (필수, 중복 불가 — 원본과 변경본 비교에 사용) |
| `type` | `place`(장소) / `move`(이동 블록: `mode`, `from`, `to`, `cost`) |
| `cat` | 식사 / 관광 / 쇼핑 / 이동 / 숙소 |
| `start`, `dur` | 시작 `HH:MM`, 소요시간(분) |
| `q` | 구글 지도 검색어 |
| `options` | 식사 1·2·3안 `[{name, q}]` (`cat`이 `식사`이고 `optLabel` 없으면 식사 자체, `optLabel`이 있으면 장소 안의 부가 식당) |
| `rain` | 우천 대체 `{name, q, memo}` |

## 현지에서 변경한 일정을 영구 반영하는 방법
1. 여행 중 **변경된 일정** 모드에서 수정합니다. (수정 즉시 폰의 브라우저 `localStorage`에 저장 — 같은 기기/브라우저에서만 유지)
2. **[변경사항 JSON 내보내기]** 로 `<trip-id>.json`을 받습니다. (선택한 식사안/우천 설정도 포함)
3. 받은 파일로 `trips/<trip-id>.json`을 덮어쓰고 커밋 & 푸시합니다.
4. 푸시 후 앱에서 **[원본으로 초기화]** 를 눌러 로컬 변경분을 비웁니다. (새 원본이 곧 변경 결과가 됩니다. 원래 계획이 필요하면 Git 기록에 남아 있습니다.)

## 로컬 실행
`fetch`를 사용하므로 파일을 직접 열지 말고 간단한 서버로 실행하세요. 예: `python -m http.server` 후 http://localhost:8000

## 배포
`main` 브랜치 루트를 GitHub Pages 소스로 사용합니다. (Settings → Pages → Deploy from a branch → `main` / `/ (root)`)
